# realestate-law-analysis — 부동산 법률 종합 분석

법령·판례 조회 결과를 사용자가 실무에서 쓸 수 있는 **근거 기반 법률 분석**으로 종합한다.

## 분석 절차
1. **도메인 판별** — 경매/공매/매매/재개발·재건축/청약 중 어디에 속하는지 판별(복합 가능).
   `law-api-query`의 `references/domain-statute-map.md` 판별 힌트 사용.
2. **쟁점 도출** — 질문에서 법적 쟁점을 구체화한다. 조사관에게 넘길 검색 키워드·법령·조문을 명시.
3. **근거 수집 지시** — 법령 조사관(조문)·판례 조사관(판례·해석례)에게 검색 대상을 배분.
4. **교차 검증 종합** — 조문 텍스트와 판례 요지를 대조. 조문의 일반 규정을 판례가 어떻게 구체화/제한하는지 연결.
5. **실무 리스크·결론** — 사용자 상황에 적용한 결론 + 리스크 + 다음 행동을 제시.
6. **인용 사후검증(게이트)** — 보고서 초안이 완성된 뒤, 최종 출력 전에 반드시 수행. 아래 "인용 사후검증" 절 참조.

도메인별 필수 점검 항목(체크리스트)은 `references/issue-checklists.md` 참조.

## 보고서 표준 구조
```
1. 질문 요약 & 도메인 판별
2. 핵심 쟁점 (bullet)
3. 관련 법령 — 법령명 제○조 [시행일] + 조문 원문 인용
4. 관련 판례·해석례 — 사건번호/선고일/법원 + 판시요지 인용 (판례일련번호 명기)
5. 적용 분석 — 사용자 상황에 조문·판례를 대입한 해석
6. 실무 리스크 & 권고 (실행 가능한 다음 단계)
7. 근거 출처 목록 (조회한 MST/판례일련번호/링크 + 검증상태 ✓/✗/⚠, "인용 사후검증" 절 참조)
8. 고지: 일반 법률정보이며 개별 사건은 변호사·법무사 상담 필요
```

## 인용 사후검증 (최종 출력 전 필수 게이트)
보고서에 인용한 조문·판례가 실제로 존재하는지, 조회 과정에서 오기·오인용이 없었는지 **초안 완성 직후, 사용자에게 보여주기 전에** 한 번 더 확인한다. (korean-law-mcp의 `verify_citations` 사후검증 기능을 참고해 도입 — `_workspace/reference_comparison.md` §4.1 참조.)

**절차**:
1. 초안 본문에서 인용된 모든 `법령명 제○조(제○항)`와 `사건번호`(판례) 패턴을 뽑아 목록화한다.
2. 각 항목을 `law_api.py`로 **재조회**한다 — 법령은 `body --target law --mst <MST> --jo <JO>`, 판례는 `body --target prec --id <일련번호>`. (스킬 안에서 이미 확보한 MST/일련번호를 그대로 써서 재조회한다. 처음 조회와 다른 값이 나오면 그 자체가 이상신호다.)
3. 판정:
   - **✓ 확인** — 재조회 결과가 보고서에 인용한 내용(조문 문언/판시요지)과 일치.
   - **✗ 불일치/부존재** — 해당 조·항이 없거나(예: 개정으로 삭제·이동), 인용한 문구가 원문과 다름. **보고서에서 즉시 수정하거나 삭제**하고, 왜 틀렸는지 남긴다.
   - **⚠ 모호** — 법령명이 유사 법령과 헷갈릴 수 있거나(예: "민법"과 "난민법"처럼 부분일치 위험), 조문 번호만 맞고 세부 항·호까지는 확인 못한 경우. 보고서에 "⚠ 확인 필요"로 표시하고 넘어간다(삭제 금지).
4. 최종 "근거 출처 목록"(구조 7번)에 각 인용마다 ✓/✗/⚠를 표시해 사용자가 신뢰도를 한눈에 보게 한다.
5. 흔한 함정 (재검증 시 반드시 체크):
   - 법령명 부분일치 오매칭(예: "민법"↔"난민법", "주택법"↔"공동주택관리법") — **완전일치 우선, 부분일치는 반드시 사람이 재확인**.
   - "같은 법", "같은 법 시행령/시행규칙" 같은 대용 표현은 **직전에 언급된 법령명을 상속**했는지 확인 (엉뚱한 법령으로 잘못 상속되지 않았는지).
   - 조문 번호뿐 아니라 **조문 제목까지** 원문과 일치하는지 대조 (번호만 맞고 내용이 다른 조문을 인용하는 사고 방지).
   - 인용한 판례가 이후 **전원합의체 등으로 변경·파기**되지 않았는지, 해당 쟁점 최근 판례를 한 번 더 검색해 변경 이력을 확인 (특히 유치권·법정지상권·조합원 지위처럼 판례 변천이 잦은 쟁점).
6. 재검증에서 근거가 무너진 인용은 절대 그대로 두지 않는다 — 삭제하거나 "✗ 확인 안 됨"으로 명시하고 결론에 미치는 영향을 재평가한다.

## 인용 규칙 (신뢰도의 핵심)
- 모든 법적 주장에는 **조문 또는 판례 근거를 병기**한다. 근거 없이 단정하지 않는다.
- 조문은 `법령명 제○조 제○항 (시행 YYYY.MM.DD)` 형식. 판례는 `대법원 YYYY.MM.DD. 선고 사건번호 판결/결정`.
- 조사에서 근거를 못 찾은 부분은 "확인된 근거 없음 — 추가 조사 필요"로 **명시**하고 창작하지 않는다.
- 조사관 산출물에 `[NOT_FOUND]`(결과 0건)와 `[ERROR:...]`(조회 자체 실패)가 섞여 있으면 **둘을 구분해서** 보고서에 반영한다 — 전자는 "관련 근거 없음"으로 결론에 반영해도 되지만, 후자는 "조회 실패로 근거 확인 못함"으로 표시하고 결론의 신뢰도를 낮춰야 한다(재조회 전에는 "근거 없음"으로 단정하지 않는다).
- 인용한 판례는 조사관이 "판례 생사 확인"(최근 변경·파기 여부)을 거쳤는지 확인하고, 안 거쳤다면 종합 단계에서 한 번 더 최신 판례를 검색해본다.
- 상충하는 판례/해석이 있으면 삭제하지 말고 **출처와 함께 병기**하고 다수·최신 견해를 표시한다.
- 개정이 잦은 규제(전매제한·투기과열지구 조합원 지위 양도·토지거래허가 등)는 **시행일 기준**을 반드시 확인.

## 왜 이렇게 하나
- 부동산 법률은 **금액·권리 상실 리스크**가 커서 "그럴 것이다"식 서술이 위험하다. 조문·판례 원문 인용이 유일한 안전장치다.
- 조문만으로는 부족하다: 유치권·법정지상권·조합원 자격·현금청산 등은 판례가 실질 기준이므로 **판례 병행**이 필수다.
- 이 스킬은 "무엇이 맞는가"를 넘어 "당신 상황에서 무엇을 해야 하는가"까지 답해야 실무 가치가 있다.
